# CP01: make the educational comparison easy to inspect

## Scope

This guide applies only to the English CP01 local comparison supplied with this task. The underlying product scene is a returning person finding a recent document. The surrounding page teaches a copy change. Neither scene needs a real account or document backend.

The fixture contains two authored specimens: Before has a welcome and a redundant instruction; After starts with recent documents. The bad copy inside Before is the evidence being discussed. Do not erase it or rewrite both specimens into the same content.

## Intended reading order

1. Identify the single case and what it illustrates
2. Compare the same two documents and action under the two headings
3. Read a short reason tied to the visible change
4. Inspect the shared data or exercise/reset the local action if useful

A control should not become the headline when there is only one case. A compact case identifier or short heading is often sufficient; retain a selector only if there is a meaningful choice. Keep reset and data inspection available without making them the main attraction.

## Content decisions

Preserve the two specimen titles/body texts, document names, modification values, order, action labels/effect, and the educational Before/After meaning. The same data and action must appear in both specimens.

In the supporting explanation, say the concrete change once: the welcome and redundant selection instruction were removed; the recent documents and their modification values remain. Avoid a formal report full of repeated preservation claims, generic rationale, or self-congratulation. The reader should be able to connect each reason to something visible.

Keep a brief local-demo disclosure near the interaction or in an easy-to-find footer. Make it clear that Find a document records an intention and does not navigate to a real service. Preserve the shared-facts disclosure even if its placement changes.

## Visual decisions

Choose a coherent palette that makes text, metadata, and action easy to distinguish. The historical gray-green wash, dark teal action, and heavy top rules are reference properties, not required project branding. A different palette is allowed; the choice needs a role rather than a claim that one hue is universally better.

Use the same interior treatment for both specimens. The authored copy difference is the comparison. Avoid giving After a visually privileged button, richer illustration, or stronger data hierarchy than Before.

Use restrained framing: a title/case label, two comparable regions, one short explanation, and secondary evidence/demo controls. Put primary document information above less useful page chrome. Keep related text close to its document; size the action to its label and hit area. Reflow to a single readable column on narrow screens without losing labels or the relationship between panels.

Do not add imagery, decorative icons, a sidebar, a banner, a feature grid, faux analytics, or broad product navigation unless this specific task requires it. This is a scope decision for this screen, not a general ban on those components.

## Checks that must survive the redesign

- Weekly meeting notes / Yesterday and Launch checklist / October 2 appear in both specimens in the same order
- Both Find a document buttons record the same local intention and clearly disclose no external action
- Repeated activation and Reset demo state work; reset does not remove the documents
- The Before title/body and After title/body remain the authored specimens
- Shared state and facts are inspectable
- The comparison remains usable with keyboard and at both specified viewport sizes
- Any final claim describes what was actually implemented and checked

## When not to apply this guide

If a later screen has several real case choices, a selector may be appropriate. If a product has useful returning-user guidance, do not delete it merely because CP01 removed a generic welcome. If color encodes a meaningful state, retain it with accessible text. Route those cases from their own task and fixture.
