**사용자 검수 전 조사 초안 · 2026-10-03 · 관찰 창 12:03–12:21 UTC**

이 문서는 유명 화면의 외형을 모으는 대신, 사용자가 대상을 찾고 판단하고 잘못된 선택에서 돌아오는 과정을 분석한다. 실험자의 관찰·해석이며 실제 사용성 시험, 전환율 실험, 사이트 제작자의 설계 의도를 대신하지 않는다.

## 0. 관찰 범위와 근거 등급

### 환경

- 브라우저: dot의 원격 **클라우드 Chrome**. 사용자의 로컬 컴퓨터·브라우저를 사용하지 않음
- 작업 호스트: 제공된 Linux 실행 환경. 원격 Chrome 자체의 OS·정확한 버전은 별도 확인하지 않음
- DOM viewport: **1180 × 757 CSS px**, devicePixelRatio **1**, visualViewport.scale **1**
- 브라우저 UI의 zoom 백분율: **미확인**. DPR 1 또는 visualViewport.scale 1을 브라우저 zoom 100%라고 해석하지 않음
- 영문 공개 화면: IKEA US, Apple US, English Wikipedia, MDN en-US, Khan Academy
- 한국어 공개 화면: Coursera. 브라우저 환경에 따라 한국어가 표시됨. 한국어를 별도로 설정하거나 계정을 수정하지 않음
- 로그인: 각 사이트의 Log in/Sign up 또는 로그인/무료 회원 가입 표시를 확인한 비로그인 공개 화면. Khan의 비로그인 진도 UI는 관찰했지만 계정 로그인이나 학습 진도 제출을 하지 않음
- 지역: IKEA 화면에 Stoughton, MA, Apple 화면에 20170/Apple Reston이 자동 표시됨. 연구자가 위치·우편번호를 입력하거나 매장을 선택하지 않았으며 사용자의 실제 위치라는 뜻이 아님
- 금지 경계: 구매, 장바구니 추가, 등록·수강 신청, 개인정보 입력, 과제 제출, 외부 AI 상담 전송을 하지 않음

### CSS px와 그림 px를 섞지 않는다

DOM은 getBoundingClientRect()·getComputedStyle()로 읽었다. 아래 수치는 모두 CSS px이며 소수점은 반올림했다. JPEG는 도구 출력 과정에서 일반 페이지가 **1165 × 747 그림 px**, 일부 모달·고정 화면이 **1180 × 757 그림 px**였다. 원인은 이번 조사에서 분리 측정하지 않았다. 따라서 스크린샷 자로 CSS 치수를 역산하지 않는다. 재측정 가능한 selector와 원수치는 같은 폴더의 JSON에 남겼다.

## 2. 쇼핑 A: IKEA, 많은 후보를 현실 조건으로 줄이는 구조

### 사용자가 끝내려는 일

‘책상이 필요하다’에서 출발해 예산·크기·색·구매 가능성을 확인하고, 선택을 계속 진행할 만한지 판단한다. 이번 종료점은 **치수 확인 후 검색으로 돌아오기**다. 주문 완료까지 검증한 것은 아니다.

### 직접 밟은 경로

1. [IKEA US 홈](https://www.ikea.com/us/en/) 진입. 검색 입력, 위치/매장, 즐겨찾기·쇼핑백·메뉴가 상단에 있음
2. 메뉴 → Products → Storage & organization. 2단계에서 **Go back**이 생기고 상위 Products로 복귀. **Close menu**로 본래 홈을 다시 사용
3. 검색에 desk 입력 → [검색 결과](https://www.ikea.com/us/en/search/?q=desk). 초기에는 Loading search results 상태를 읽었고 이후 190개 상품이 표시됨
4. Price 펼침 → $0.00–99.99 선택 → 결과 57개. 선택 칩과 해제 버튼이 등장하고 URL에도 필터가 반영됨
5. 활성 필터 제거 → 체크 해제, 원래 URL과 190개 결과로 복귀
6. MICKE 41 3/8 × 19 5/8 상품 선택 → [상세](https://www.ikea.com/us/en/p/micke-desk-white-80213074/)
7. 상품명 옆 치수 버튼 → Measurements 탭/도면·하중·폭·깊이·높이 표로 이동. URL은 같은 상품 주소를 유지
8. 브라우저 뒤로 → 검색 결과 URL 복귀. 필터·스크롤의 모든 조합에 대한 복원은 별도 미검증

### 정보 구조와 동선

- **탐색 메뉴:** 제품·방·할인·아이디어·서비스가 하단 탭에 있고 제품군을 누르면 서랍 안의 다음 깊이로 들어간다. 480px 서랍은 이 viewport의 약 40.7%다. 이것은 면적 미학 비율이 아니라 현재 화면에서 원래 문맥이 얼마나 남는지 설명하는 값이다
- **검색 화면:** 검색 조건은 왼쪽, 비교 대상은 오른쪽 3열. 상품 사진은 1:1로 통일돼 사진 외곽의 비교 기준을 안정시킨다
- **카드 내부 순서:** 비교 → 이미지/상품 상태 → 이름·종류·치수 → 가격 → 리뷰 → 재고 → 다른 옵션. 상단에서 형태를 훑고 아래로 갈수록 구매 불확실성을 해소하는 순서다
- **상세 화면:** 큰 이미지·썸네일은 왼쪽, 상품·가격·평점·색·수령·수량·담기는 오른쪽. 치수는 제목 바로 옆 진입점과 아래 별도 탭 양쪽에 있다
- **깊이의 의미:** 2단 메뉴 자체보다, 상위로 한 단계 되돌리는 버튼과 메뉴 전체를 닫는 버튼이 별도라는 점이 중요하다. ‘뒤로’와 ‘닫기’의 결과가 다르다

### 색·밀도·치수

- 넓은 흰 배경은 사진·텍스트를 읽는 바탕이다. 파랑은 담기 같은 주 행동, 분홍 Best seller는 상품 상태, 초록 점은 재고 표시로 사용됨. 재고에는 ‘In stock’ 텍스트가 함께 있어 색에만 의미를 맡기지 않는다
- 검색 카드 폭 260.33에 이미지 240.33. 양옆 약 10씩 내부 여유가 있고, 이미지보다 이름·치수 텍스트 구획이 더 좁다. 실측 카드 제목 링크 자체는 짧은 상품명 너비여서 카드 전체 클릭 영역과 혼동하면 안 된다
- 검색 필터를 좁히자 관련 필터의 개수도 바뀌고 0개 조건은 비활성 표시가 나타났다. 빈 결과를 만든 것은 아니므로 ‘빈 결과 복구가 검증됨’이라고 쓰지 않는다

### 왜 이 용도에 맞는가 / 단점 / 복제 금지 조건

- **좋은 점:** 가구 구매의 핵심인 크기·예산·재고를 상품 홍보에서 분리하지 않는다. 상세 첫 화면에서 치수 검토로 바로 이동할 수 있어 잘못 맞는 물건을 고르는 비용을 낮출 가능성이 있다
- **단점:** 처음 검색 결과에 책상뿐 아니라 서랍 유닛·상판도 함께 보였다. ‘desk’가 완제품만 뜻한다고 기대하는 사람은 유형 필터를 추가로 이해해야 한다. 카드의 할인·매장 가격·회원 혜택은 늘어날수록 비교가 느려진다
- **복제하지 말 것:** 상품이 5개뿐인 소규모 상점에서 동일한 긴 필터 사이드바를 만들 필요는 없다. 사진·형태보다 텍스트 차이가 핵심인 디지털 상품에는 1:1 이미지 카드가 공간 낭비가 될 수 있다
- **설계 규칙으로 바꾸면:** 후보 수가 많을 때는 결과와 필터를 동시에 유지하고, 선택한 조건은 독립적으로 해제할 수 있게 하며, 치명적인 적합성 정보는 상세 최상단에서도 열 수 있게 한다

### 오류·취소·복귀 경계

가격 필터의 적용·해제, 메뉴 한 단계 뒤로·닫기, 상세에서 브라우저 뒤로는 D다. 재고 조회에서 처음 Checking availability 표시 후 상세는 배송/재고 확인 안내로 바뀌었지만 주소를 넣지 않아 배송 가능성은 미확인이다. 결제 거절·주소 오류·품절 전환·저장 목록 실패는 미검증이다. 자동화 도구가 숨겨진 체크박스 input을 직접 누르지 못해 실제 label을 사용한 것은 **도구 상호작용 한계**로 기록하며 사람의 클릭이 안 되는 사이트 결함으로 판단하지 않는다.

## 3. 쇼핑 B: Apple, 서로 의존하는 선택의 결과를 드러내는 구조

### 종료점과 직접 경로

[MacBook Air 구성기](https://www.apple.com/shop/buy-mac/macbook-air) → 13-inch → Sky Blue → 10-core CPU/8-core GPU → Unified Memory 편집 → 24GB의 가격·변경 사항 보기 → 연쇄 변경 비교 → **Keep what I have**. 여기서 종료했다. Buy/Finance/Lease 선택이나 Continue 이후를 진행하지 않았다.

### 단계 설계

- **D:** 초기에는 크기만 선택 가능하고 색·칩·하위 결정은 비활성. 크기 선택 후 색이, 색 선택 후 칩이 활성화됐다
- **D:** 칩을 고르면 메모리·저장 공간·전원·키보드가 ‘현재 값 + Edit’로 바뀐다. 기본안을 먼저 제시하고 필요한 수정만 펼치는 구조다
- **D:** 24GB를 누르자 16GB→24GB뿐 아니라 GPU 8코어→10코어가 바뀌는 비교 화면이 열렸다. 현재/변경 구성을 두 열로 놓고 당시 표시 총액 $1,299→$1,499를 각각 보여줬다
- **D:** 사용자가 원하지 않으면 Keep what I have로 모달을 닫고 16GB 구성 URL·상태를 유지했다. 이는 구매 취소가 아닌 **미적용 구성 제안 취소**다
- **I:** 단순 비활성화로 ‘안 된다’만 알리는 대신 가능한 연쇄 수정과 비용을 설명한다. 의존성이 많은 주문 제작·여행 옵션·업무 권한 설계에서도 중요한 패턴이다

### 공간·크기·정보 순서

문제 답안 제출, 틀린 답 피드백, 힌트 사용, 중단한 과제 복귀, 계정 간 동기화, 자막 동기화·플레이어 키보드 조작, 모바일은 미검증이다. 본문 링크의 AX 표기는 ‘Opens a modal’이지만 실제 주소가 영상 경로로 바뀌고 넓은 학습 화면이 렌더링되어 단순 작은 팝업이라고 설명하지 않는다.

## 7. 강의 B: Coursera, 등록 전 적합성 판단과 커리큘럼 탐색

### 범위를 먼저 밝힌다

이번 사례는 **강의를 고르는 공개 카탈로그 UX**다. 등록 후 학습실의 UX는 아니다. 한국어 화면의 Learning How to Learn 과정을 관찰했고, 로그인·수강 등록을 하지 않았다. 검색 카드에 ‘미리 보기’ 표시가 있었으나 실제 공개 재생 경로는 검증하지 않았다.

### 직접 경로

1. [과정 상세](https://www.coursera.org/learn/learning-how-to-learn) 확인
2. 4개 모듈 링크 → #modules
3. 첫 모듈 펼침 → 설명·자료 종류/개수 → 내부 콘텐츠 정보 다시 펼침 → 영상·읽기·과제·동료 평가 항목과 시간
4. 내부 목록 접기 → 모듈 접기. 인접 모듈 목록으로 돌아갈 수 있음
5. ‘강의와 과제는 언제 이용할 수 있나요?’ FAQ 펼침으로 접근 조건 설명 확인. 등록 방식에 따라 접근 범위가 다르다는 설명만 읽고 신청하지 않음
6. 상단 카탈로그 검색 learning how to learn → [결과](https://www.coursera.org/search?query=learning%20how%20to%20learn) → 해당 과정 링크 클릭 → **새 탭**에 같은 과정 상세가 열림. 검색 탭은 유지됨

### 구조와 순서

- 검색 카드: 제공자 → 제목 → 스킬 → 평점·리뷰 수 → 수준·과정 유형·예상 기간 → 미리보기 표시. 브랜드 이미지와 공급자 신뢰, 시간·난이도 적합성을 함께 비교
- 상세 첫 화면: 제공자/과정명/강사 → 등록 CTA와 등록자 수 → 모듈·평점·초급·예상 기간 요약 → 얻을 스킬·세부 정보 → 커리큘럼 → 리뷰·FAQ
- 긴 상세를 스크롤하면 과정명·등록 CTA·섹션 탐색이 위에 남는다. 사용자는 근거를 더 읽은 다음 등록 진입점을 다시 찾을 필요가 줄어든다
- 모듈은 ‘개요→자료 종류→개별 항목’의 2단 disclosure다. 처음에는 전체 4모듈의 윤곽을 훑고, 관심 모듈만 깊이 본다

### 치수·색·밀도

- 제목 44/52, 600 weight, 616.91 폭에서 3줄·156 높이. 한국어 긴 제목과 번역 길이의 효과를 포함하므로 영문판과 직접 비교하면 안 된다
- 첫 등록 CTA 252.64×48, 파랑 rgb(0,86,210)/흰 글자, 16px. 검색 입력 394×48
- 검색 카드 콘텐츠 폭 341, 제목 영역 325. 동일 3열 카드지만 IKEA처럼 가격·재고가 아닌 스킬·수준·기간이 비교축이다
- 첫 모듈 펼침 버튼은 조사 당시 568.25×76, 텍스트 기본 16/24. 패널 닫기와 반응형 재배치 뒤 실제 폭이 바뀔 수 있어 안정 상태 재측정을 권장한다
- 첫 방문에서 오른쪽 상담 패널이 열려 본문 폭을 줄였다. 실제 ‘채팅 닫기’ 버튼으로 닫았고, 메시지나 개인정보를 전송하지 않았다. 사이트가 외부 AI 질문을 화면에 제시해도 연구자의 지시로 따라 하지 않았다

### 좋은 점·나쁜 점·복제 금지

- **좋은 점:** 수강 전에 내용·난이도·시간·언어·평가 유형을 판단할 정보를 제공한다. 과정별 다른 콘텐츠를 비교 가능한 구조로 만든다
- **나쁜 점 D:** 관찰된 한국어 화면에는 모듈 설명 속 `<br><br>` 문자열, 일부 부자연스러운 번역, 검색 결과 총개수 숫자가 비어 있는 표현이 보였다. 이 세션의 표시 문제로 기록하며 모든 언어·사용자에 일반화하지 않는다
- **나쁜 점 I:** 등록을 권하는 CTA가 커리큘럼·접근 조건보다 먼저 나오고, 실제 샘플·접근 범위의 명료성은 부족하게 느껴질 수 있다. 상담 패널은 주 콘텐츠 공간과 경쟁한다
- **복제 금지:** 내부 필수교육처럼 선택지가 없는 상황에서는 후기·등록자 수·대규모 마케팅 영역보다 시작/재개·필수 완료 조건이 먼저여야 한다
- **적용 규칙:** 등록 전에는 ‘나에게 맞는가’를, 등록 후에는 ‘지금 무엇을 해야 하는가’를 우선한다. 선택 전의 설득 구조를 학습 중 작업 화면에 그대로 가져오지 않는다

### 취소·복귀·미검증

모듈·내부 자료 목록의 접기, 상담 패널 닫기는 D다. 브라우저 뒤로는 #modules를 제거했지만 당시 화면은 모듈 근처를 유지했다. 따라서 ‘뒤로 하면 상단으로 돌아간다’는 규칙을 주장하지 않는다. 이후 Control+Home으로 상단 이동만 확인했다. 공개 샘플 재생, 등록 실패, 취소·환불, 진도 저장, 퀴즈 오류, 키보드 전체 탐색은 미검증이다.

## 8. 비교를 실제 설계로 바꾸는 법

### 유형별 작업 완료 정의부터 다르게 잡는다

| 유형 | 진짜 작업 | 남겨야 할 문맥 | 지연 공개할 것 | 실패 시 돌아갈 자리 |
|---|---|---|---|---|
| 쇼핑 검색 | 후보를 조건에 맞게 줄이고 적합성을 판단 | 검색어·활성 필터·비교 대상 | 상세 사양·부가 서비스 | 이전 목록·조건·스크롤 |
| 쇼핑 구성 | 유효한 조합과 비용을 이해 | 현재 구성·총액·종속 관계 | 고급 변경 옵션 | 변경 전 구성 |
| 정보 읽기 | 필요한 답을 찾고 근거를 확인 | 문서 위치·상위 주제·현재 절 | 전체 분류·보조 설정 | 원문 절·인용 위치 |
| 강의 선택 | 내용·난이도·시간·접근 조건 판단 | 현재 과정·모듈 윤곽 | 세부 수업·과제·후기 | 검색 후보·관심 모듈 |
| 강의 학습 | 이해하고 연습하며 다음 단계 진행 | 과정/단원/수업·진도 | 토론·설정·보조 자료 | 중단 지점·틀린 문제 |

### ‘좋은 UI 숫자’를 베끼기 전에 묻는 12문항

1. 메뉴는 사이트 전체, 현재 객체, 현재 문서 중 무엇을 바꾸는가?
2. 깊이가 늘 때 상위로 한 단계 돌아가기와 전체 닫기를 구분했는가?
3. 목록을 떠났다가 돌아오면 검색어·필터·스크롤·선택이 얼마나 유지되는가?
4. 선택 하나가 다른 값을 바꿀 때, 적용 전에 영향과 비용을 설명하는가?
5. 비활성 상태는 왜 사용할 수 없는지 알려주는가?
6. 제목/사진/수치/상태가 실제 비교 순서와 일치하는가?
7. 고정 패널을 합친 후 작업 본문에 남는 폭·높이는 얼마인가?
8. 색은 행동·상태·분류 중 어느 역할이며 텍스트·기호로 보강되는가?
9. 정보는 숨겼다가 찾게 만드는 비용보다 초기 노출 부담이 더 큰가?
10. 로딩 중과 실패·빈 결과·권한 없음이 서로 다른 설명과 복구를 갖는가?
11. 모바일, 200% zoom, 키보드, 화면 낭독에서도 같은 작업이 가능한가?
12. 단계 수·클릭 수가 줄었어도 오판·되돌림 비용이 늘지 않았는가?

### 이번 조사로 아직 주장할 수 없는 것

- ‘전환율이 높다’, ‘사용자가 더 빠르다’, ‘접근성 준수’, ‘모바일에서도 동일하게 좋다’
- 전체 페이지의 대표색 면적을 근거 없이 60:30:10 같은 공식에 맞춘 주장
- 이미지 px를 CSS px로 둔갑시킨 정밀 수치
- 버튼이 화면에 있다는 이유만으로 성공·오류·취소를 모두 검증했다고 하는 주장
- 한 번의 자동화 실패를 사람의 사용 실패 또는 서비스 장애로 해석하는 주장

## 10. 증거 파일과 재측정 방법

원본 제품 화면 캡처는 공개 자료에 포함하지 않는다. 관찰 설명과 연결한 원문 출처를 함께 읽는다.

- 원본 캡처 22개 JPEG. 각 이미지의 그림 px 크기는 `evidence_manifest.json`에 기록
- raw 측정 JSON: `wikipedia_initial_metrics.json`, `mdn_initial_metrics.json`, `ikea_search_metrics.json`, `apple_modal_metrics.json`, `khan_lesson_metrics.json`, `coursera_overview_metrics.json`, `supplemental_metrics.json`
- 보완 실측과 흐름 이벤트: `observation_log.json`
- 재측정 스니펫: `measurement_method.js`. 브라우저의 허가된 read-only evaluate에서 사용하며 숨겨진 상태·계정 데이터에 접근하지 않음

수치는 각 selector의 첫 렌더링 요소에서 가져왔다. 같은 이름의 복제·숨김 요소가 있을 경우 rect와 스크린샷을 함께 확인해야 한다. 요소마다 border-box, 콘텐츠 영역, 실제 클릭 면적이 다르므로 이름을 보존한다. 측정 예시를 제품 구현 코드나 자동화 테스트 통과 보고서로 오해하지 않는다.

원본 제3자 제품 화면은 재배포 권한이 확인되지 않아 이 자료에 포함하지 않았다. 자체 관찰 설명을 현재 제품의 실측이나 사용성 개선 결과로 확대하지 않는다.
