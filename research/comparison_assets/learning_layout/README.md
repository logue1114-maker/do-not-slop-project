# 학습 화면: 같은 데이터, 다른 구조

직접 만든 가상 학습 앱의 구조 비교판입니다. 실제 Moodle 등의 제품 화면을 복제한 개편안이 아니며, 측정된 사용성 개선을 주장하지 않습니다. 사용자 승인 상태는 **pending / 검수 대기**입니다.

## 열기

`same_fixture_learning.html`을 브라우저에서 엽니다. 외부 라이브러리·폰트·이미지·fetch·로그인이 없어 파일 하나로 동작하도록 작성했습니다. 실제 브라우저로 열어 렌더링하는 검수는 아직 실행하지 않았습니다.

- 넓은 화면: 수정 전/후를 나란히 배치하도록 CSS를 작성했습니다
- 900px 이하: 수정 전/후 버튼으로 한쪽을 표시하도록 작성했습니다
- 어느 화면에서든 강의를 열고 확인 문제에 답하면 같은 상태가 양쪽에 반영됩니다
- 진행은 현재 페이지 메모리에만 남습니다. 새로고침, 비교 상태 변경, 초기화는 해당 fixture의 시작 상태로 돌아갑니다

## 고정한 비교 계약

강의는 같은 3개입니다: 관찰에서 가설까지 / 인터페이스 글쓰기 / 작은 화면의 읽기 설계.

각 강의의 제목·분류·수준·학습 목표·준비물·무료 조건·전체 시간·수업 수·완료 수·진행률·다음 수업명·시간·썸네일·행동이 같습니다. 모든 수업은 직접 쓴 텍스트와 동작하는 확인 문제를 포함합니다. 비디오를 흉내 낸 플레이어나 기능 없는 버튼은 없습니다.

- 실제 실행 시 JSON을 한 번 읽고 불변 `fixture` 하나와 변경 가능한 `state` 하나만 만듭니다
- 두 화면은 같은 `courseSnapshot`, `renderLesson`, `dispatch`를 씁니다. 수정 전/후별 진도·답·선택 상태를 따로 두지 않습니다
- `fixture.json`은 검토 가능한 원본 사본이고 HTML은 동일 JSON을 내장합니다. 두 파일의 정확한 일치를 테스트합니다. 둘을 독립적으로 수정하면 테스트가 실패합니다
- 수정 전은 원래 강의 순서를 유지합니다. 수정 후는 선택한 현재 강의를 맨 위로 옮기고 나머지 두 강의를 원래 상대 순서로 표시합니다. 삭제하거나 새 강의를 더하지 않습니다
- 현재 강의는 수정 후의 큰 첫 행, 나머지는 압축 행입니다. 각각 같은 고유 사실을 한 번씩 표시합니다
- 연 수업의 본문·문제·답·피드백·행동도 두 화면에 같습니다. 수정 후에서 수업 영역의 DOM 순서만 강의 목록 앞으로 옮깁니다

## 실제 동작

1. **학습 열기:** 첫 미완료 수업을 엽니다. 현재 강의 선택도 양쪽에 반영합니다
2. **정답 확인:** 미선택과 오답에는 복구 안내가 나오고 완료는 막힙니다. 답을 바꾸면 기존 정답 확인이 취소됩니다
3. **학습 완료:** 확인한 정답이 있을 때만 완료 수를 올리고 다음 미완료 수업을 엽니다. 마지막 수업이면 열린 수업을 닫고 강의를 100%로 표시합니다. 중복 완료는 막습니다
4. **처음부터 복습 / 복습 마치기:** 이미 완료한 강의의 첫 수업을 실제로 엽니다. 복습은 기존 진행을 바꾸지 않습니다
5. **수업 닫기:** 진행을 남기고 수업을 닫습니다
6. **비교 상태 / 초기화:** 기본, 빈 목록, 전체 완료, 긴 한글 제목을 양쪽에 동시에 적용합니다. 빈 목록의 불러오기 버튼은 기본 3개 강의를 복원합니다

## 화면 교정 지시 → 코드 → 검수

### V05: 기본 섹션 순서를 내용의 순서로 바꾼다

- 지시: 환영 → 사용법 → 동일 카드의 순서를 현재 학습 → 나머지 강의로 바꾼다
- 코드: `renderView('after')`는 `generic-hero`, `redundant-guide`를 생성하지 않습니다. `task-course-list`는 현재 강의 `course-focus`와 나머지 `course-row`로 구성합니다
- 공간: `.generic-hero`의 최소 높이 176px와 `.redundant-guide`의 최소 높이 78px는 수정 전 전용입니다. 수정 후에는 컨테이너 자체가 없어 해당 슬롯·여백을 유지하지 않습니다. 이 값들은 작성한 CSS 값이며 실제 제품 실측값이 아닙니다
- 수락 조건: 강의 개수, 고유 사실, 썸네일 정보, 행동의 의미와 활성 상태가 양쪽에 같아야 합니다. 이 조건의 소스 테스트는 통과했습니다

### V06: 앱 안에서는 수업이 화면의 중심이다

- 지시: 현재 강의의 다음 수업명·소요 시간·학습 열기를 한 덩어리로 묶는다. 수업을 열면 본문과 응답을 먼저 놓는다
- 코드: `.course-focus .next-task`에 다음 수업을 강조하고 `renderLesson()`을 수정 후의 목록 앞, 수정 전의 카드 뒤에 배치합니다. 학습 자료나 문제의 양은 줄이지 않습니다
- 상태: `OPEN_COURSE`, `ANSWER`, `SUBMIT_ANSWER`, `COMPLETE_LESSON`이 하나의 `state`를 변경한 뒤 양쪽 `render()`를 호출합니다
- 수락 조건: 어느 쪽의 버튼을 눌러도 동일 수업·선택 답·정오 피드백·완료 상태·다음 수업을 보여야 합니다. 소스 이벤트 경로와 DOM 순서는 통과했습니다. 실제 첫 화면의 시각적 중심은 브라우저/사용자 검수 대기입니다

### V07: 중복 설명과 그 빈 자리를 함께 제거한다

제거한 문장은 다음뿐입니다.

- “배움의 가능성을 열어 보세요 / 작은 시작이 더 큰 내일을 만듭니다 / 오늘도 나만의 성장 여정을 이어가세요”: 분위기 문구. 이 가상 앱의 수업 선택·조건 판단에 새 사실을 제공하지 않습니다
- “아래 강의 목록에서 원하는 강의를 선택하면 수업 내용을 확인하고 학습을 시작할 수 있습니다”: 제목과 `학습 열기` 버튼이 이미 드러내는 사용법

학습 목표, 준비물, 무료·가입 조건, 다음 수업 시간, 완료의 결과, 오답 복구, 복습에서 진행이 바뀌지 않는 사실은 그대로 남겼습니다. 삭제된 안내 컨테이너의 빈 높이나 새 홍보 카드를 만들지 않았습니다.

- 코드: 사실은 `courseFacts()`, `nextTask()`, `renderLesson()`이 양쪽에 같은 `data-fact-key/value`로 렌더합니다
- 수락 조건: 정답 확인 전 완료 불가, 오답 복구, 완료 후 진행 갱신, 복습의 기존 진행 유지가 같아야 합니다. 소스 테스트는 통과했습니다

### 좁은 화면과 긴 제목

- 지시: 제목을 짧게 바꿔 수정 후만 유리하게 만들지 않는다. 같은 긴 한글 제목을 양쪽에 적용하고 행이 내용만큼 늘어나게 한다
- 코드: `long_title`은 공유 제목 값 하나를 변경합니다. `word-break: keep-all`, `overflow-wrap: anywhere`, `min-width: 0`을 사용하고 line-clamp/말줄임은 쓰지 않습니다. 압축 행에는 고정 높이를 두지 않았습니다
- 수락 조건: 320px·390px, 200% 글자 확대에서 제목·준비물·무료 조건·버튼이 잘리거나 겹치지 않아야 합니다. **소스 규칙 확인만 완료, 실제 렌더링은 not_run**

## 소스 검수

공개 소스용 전체 검사: `python3 tests/test_source.py`

포함된 독립 상태 검사: `node tests/state_checks.mjs`

공개 소스용 새 검사 결과: **245/245 통과, 0 실패, 18개 렌더 소스 상태**. 이 합계에 포함된 JavaScript 상태 하네스는 29개 검사를 실행합니다.

- 실제 HTML 인라인 JS를 Node VM에서 최소 DOM stub과 함께 실행합니다
- 출력한 HTML 문자열을 Python HTMLParser로 파싱해 고유 사실·강의 개수·명령·활성 상태·진행 aria 값·radio 선택·ID/label을 비교합니다
- 렌더된 버튼/라디오의 속성을 읽어 실제 인라인 이벤트 핸들러에 연결하는 소스 수준 클릭/변경 경로를 검사합니다. 이것은 브라우저 클릭 테스트가 아닙니다
- 선택한 불투명 색 토큰 쌍은 계산상 최소 4.5:1을 통과합니다. 실제 렌더링·그라디언트·안티앨리어싱·사용자 스타일을 포함한 접근성 판정은 하지 않았습니다

과거 정적 검토 결과는 포함하지 않습니다. 새 공개 검증기는 `tests/source-test-results.json`과 요약을 기록합니다. 수치는 소스/DOM 형태 검사 범위이며 실제 브라우저·접근성·사용성 성공을 뜻하지 않습니다.

## 아직 통과하지 않은 게이트

- 데스크톱/모바일 실제 렌더링: **not_run**
- 200% 확대, 키보드 포커스 복원·탭 이동, 스크린 리더 피드백·진행 읽기: **not_run**
- 실제 가독성·시각 중심·사용자 과업 성공률: **not_run**
- 사용자 승인: **pending**


권장 다음 검수는 지원 브라우저에서 1280/1440px 데스크톱, 320/390px 모바일, 200% 확대를 확인하고 수업 열기 → 오답 → 정답 → 완료 → 복습을 키보드로 반복하는 것입니다. `innerHTML` 재렌더 뒤 포커스 복원이 실제로 유지되는지와 숨겨진 모바일 패널의 읽기 순서를 특히 확인해야 합니다. 그 결과와 사용자 검토 없이 승인 상태를 바꾸면 안 됩니다.
