# Bounded browser verification

Entry: the actual standalone `index.html` via `file://`, headless installed Chromium, DPR 1, 100% zoom. The visual promise is five distinct synthetic game contexts with readable primary actions and available keyboard/narrow-screen controls. Screens were reviewed locally; no external visual readiness certification is claimed.

The final browser run passed **77 checks, 0 failed**. It exercised native UI clicks and keyboard input without state injection. Each of the five genres was captured and measured at **1165×747** and **390×844** CSS pixels from scroll position zero. All enabled main actions and resets fit inside the viewport with a 16px bottom clearance in the measured default/blocked/preview states. No horizontal overflow, control-text overflow or browser console/page error was found in those states. Two final checks confirm that strategy vector endpoints align with the actual unit/target hitboxes within 2 CSS pixels at both widths.

Meaningful paths: RPG blocked rank → available equip → Return → reopen; card unaffordable selection → Focus/Burst → repeat prevention → shield/end turn → natural win and loss/retry; puzzle wall → natural five-move solve → undo solved state → retry, plus equivalent arrow-key solve; strategy target without unit → preview → confirm → cancel with prior order → blocked water and committed-line identity; action empty pulse → blocked repeat → paused cooldown → resume → inactive-genre freeze → two in-range pulses → gate win, plus three collisions → loss → retry.

The final source has **19 runtime captures**: 10 canonical genre/viewport captures, one early RPG desktop capture from the final run, one desktop Pause capture, and seven narrow state captures covering blocked rank, equipped equipment, card win, puzzle solved, strategy blocked target with prior order, action Pause and loss. Their viewport/state/hash records are in `qa-report.json` and `state-evidence.json`. `contact-sheet-desktop.png` and `contact-sheet-narrow.png` show the ten canonical images uncropped; the originals are authoritative. `screenshot-manifest.json` records dimensions, byte sizes and SHA-256 for both final and preserved evidence.

Local image inspection confirmed genre-specific geometry, labels and hierarchy. Original round player/diamond sentry silhouettes are kept circular/square after narrow reflow. The strategy map keeps unit identity and a separate pending/committed line. The narrow Pause modal exposes Resume and Retry while dimming the frozen arena.

Separate calculations passed **41 explicit text contrast pairs** against the chosen 4.5 ratio check. This includes the scoped disabled labels even though that is not a general conformance assertion. It does not cover every focus/boundary/color adjacency or certify WCAG compliance. A 583×374 CSS viewport was used for an equivalent 200% reflow probe; true browser 200% zoom was not run.

Keyboard checks are spot checks, including scoped shortcuts, native Enter/Space activation, Escape cancellation/resume and visible focus. A complete traversal of every map target and every Tab/Shift+Tab transition was not run. Document-hidden cooldown suspension is implemented but not directly tested; inactive-genre and modal-pause suspension were tested. Native phone, physical touch/safe-area hardware, controller, screen reader, participant usability, timing accessibility, latency/performance and production-game tests remain **not run**.

The first run's 74 passes/1 failure and pre-repair screenshots are retained under `first-pass/`. That failure and additional visible viewport problems were repaired in the same fixture, as recorded in `REPAIR_LOG.md`. Browser checks are implementation evidence, not evidence that a design guide improves model output. There was no unguided baseline, randomized trial, measured success rate or effectiveness experiment.
