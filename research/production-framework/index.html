03 / SHARED LAYERS

Layer space and input ownership

Menus, HUD, world prompts and announcements occupy the same screen. Drawing each in isolation leaves collisions unresolved.

Input owner: world
GEOMETRY

Shared coordinates, protected scene bounds, readable ink and actual hit regions

INPUT

One owner for each active gesture; dismissal must not activate the layer beneath

LIFETIME

Persist, replace, compact or queue; record what restores and when

Concurrency and interruption contract

Register each simultaneous layer with owner, anchor/bounds, priority, lifetime, input ownership and collision policy. Inspect the real worst supported combination. Essential live hazards remain visible unless the actual game state makes them irrelevant. Increasing z-order only decides which thing gets hidden; it does not solve the conflict.

04 / CONTROL ANATOMY

Target, silhouette, face and ink

Target is interaction. Silhouette is recognition. Face is the reading surface. Ink is the actual label, icon and state.

FACE WIDTH

left inset + optional icon + present gaps + measured label + optional status + right inset

HEIGHT

real line height + breathing room + selected rim/body allowance

Keep the target steady. A justified press can move the inner face while the target and neighboring layout stay fixed.

Allow an honest flat control. Body, rim, icon and equal width are choices with conditions, not mandatory polish.

05 / ART GRAMMAR

Material, type and color families

Contour, material, type, texture and color must have a named relation to the real scene and the action's rank.

These are original teaching specimens. Choose and measure the actual project's grammar; the framework does not prescribe these palettes, fonts or materials.

06 / ORNAMENT & INK

Ornament-safe content

An ornamental border has a different job from a readable face. Draw their contract before placing text.

Fixed corners / scalable center / independent type

Clip content before the rim. Reserve the header, list viewport and footer inside the declared face. Keep close/back targets discoverable.

Scale only what may scale. Plain geometric controls can stay native/code-drawn. Detailed artwork needs fixed edges, a stretch/tile center and a minimum text-safe size.

07 / MEANING & STATES

Selection, focus and feedback

Commands, navigation, toggles, values and read-only status need distinct semantics. State must survive without motion or hue alone.

State and input checks

Inspect rest, hover only where supported, keyboard/controller focus, press, persistent selection, unavailable reason, pending and error. Check a selected control while focused, release-away, cancel, rapid repeat, long labels, fallback fonts and reduced motion. A still does not establish a hit region or successful activation.
