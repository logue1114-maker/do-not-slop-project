# 전략 게임 선택 명령 카메라 HUD 교정 조사

조사일 2026년 10월 4일 UTC · 이름공간 STRAT4 · 범위는 함대 선택과 명령 지정, 카메라 입력, 현재 상태, 작은 HUD로 한정한다.

핵심 제안은 선택한 집단, 지금 지정 중인 명령, 이미 실행 중인 행동을 서로 다른 상태로 표시하는 것이다. 화면을 넓히기 위해 HUD를 줄여도 이 세 정보와 취소 경로는 남긴다. 아래 원제작자 사례는 특정 제작 단계의 설명과 정지 이미지이며, 현재 제품을 직접 플레이한 검증은 아니다. 별도 합성 전후 데모에서도 양쪽의 데이터와 조작 의미를 고정해야 한다.

## 원출처와 실제 관찰

### Homeworld 3 카메라와 명령 충돌

[Lance Mueller의 공식 개발자 글](https://www.homeworlduniverse.com/war-games-feedback/)은 2024년 3월 27일 게시되었다. 페이지 메타데이터의 게시 시각은 18:03:54 UTC이다. 글은 War Games 데모 이후의 출시 전 변경을 다룬다. 제작자는 카메라 키와 함선 명령의 충돌, Spacebar의 의도치 않은 생산, 이동과 공격 선의 동시 표시, HUD 배율 조절을 설명한다.

[공식 HUD 비교 이미지](https://www.homeworlduniverse.com/wp-content/uploads/2024/03/HUD-Scale-Before-Vs-After-1024x288.jpg)를 실제로 열어 확인했다. 상단 띠, 좌측 목표, 우측 생산 목록, 하단 선택과 명령이 화면 가장자리에 모인다. 오른쪽 표본의 하단 요소는 더 작은 덩어리로 보인다. 두 표본의 장면과 선택 내용이 달라 가림 면적이나 효율의 전후 측정 자료로 쓸 수 없다. 1024×288은 이미지 자체 크기이며 UI의 CSS 크기가 아니다.

교정 지시 STRAT4:R02: 입력 라우팅을 카메라, HUD, 월드 대상으로 분리하고 현재 바인딩에서 표시 문구를 생성한다. 카메라 조작으로 명령이 실행되지 않게 한다. HUD를 클릭하면 월드 클릭 처리로 넘어가지 않는다. 키 충돌은 전부 비활성화하는 대신 충돌 대상만 설명한다. 전후 시안은 같은 라우팅을 사용한다. 잘못된 라우팅을 고친 결과를 단순 시각 개선의 성과에 합치지 않는다.

교정 지시 STRAT4:R03: 하단 문맥 영역에 집단 이름과 수, 현재 이동, 현재 교전, 지정 중인 명령을 함께 둔다. 명령 버튼은 이동과 전투로 묶되 모든 동작과 실제 키를 보존한다. 이동 중 교전이 가능한 게임이라면 상태를 하나의 배타적 문자열로 덮어쓰지 않는다. 명령 미리보기는 점선과 ‘지정 중’, 확정 경로는 실선과 ‘명령 기록됨’처럼 텍스트와 형상도 구분한다. 실제 엔진에서 움직임이 확인될 때만 ‘이동 중’으로 표현한다. 이는 자체 제안이며 원작의 색 또는 선 모양 규정이 아니다.

예외: 글의 Modern과 Legacy는 같은 우클릭도 다른 의미로 사용한다. 따라서 장르 공통 단축키나 우클릭 의미로 옮기면 안 된다. 작은 HUD의 글자와 조작 목표가 너무 작아지면 밀도 감소나 상세 접기를 먼저 시험한다. 함선 모델 확대 NLIPS는 선택 가능성과 실제 크기감을 바꾸므로 순수 HUD 축소와 별도 변경으로 다룬다.

### Homeworld Vast Reaches 선택과 hover의 독립 상태

[Josh Squires의 제작자 포트폴리오](https://www.joshsquiresdesign.com/homeworld-vast-reaches-gameplay-ui)는 FarBridge의 VR UX/UI 담당자가 집단 조작과 상태 도식을 설명하는 원출처다. 게시일은 표시되지 않는다. 2023년 4월부터 2025년 5월이라는 프로젝트 기간을 게시일로 쓰지 않는다. 제작자는 원거리 개별 함선 조작 대신 strike group을 접점으로 사용했다고 설명한다.

Selected Idle, Selected Hover, Unselected Idle 원본 도식을 실제로 열었다. 선택 표본에는 개별 체력 막대와 A 표식 주변의 추가 segment가 있고, 비선택 표본에는 그 둘이 없다. Hover 표본에는 넓은 타원형 링과 회전 설명 화살표가 추가된다. 회전은 원저자의 설명이고 이번 정지 이미지 관찰로 애니메이션을 검증한 것은 아니다. 화살표는 도식의 주석이며 실제 HUD에 복사할 요소가 아니다.

교정 지시 STRAT4:R01: selected, hovered, keyboard focused, command armed를 별도 상태 필드로 둔다. 선택은 지속되는 집단 ID와 선택 표식, hover는 일시적 외곽 강조, keyboard focus는 별도 outline으로 표현한다. 명령을 고르면 ‘이동 목적지 지정 중’ 같은 문구와 취소 조작을 추가하지만 선택 표식은 유지한다. Escape로 명령만 취소했을 때도 같은 집단이 선택되어 있어야 한다. 선택 자체가 이동이나 공격을 실행해서는 안 된다.

예외: VR의 집단 접점, 원거리 공간 링, 잡아서 놓기는 데스크톱 마우스 조작으로 그대로 옮길 근거가 없다. 개별 함선을 정밀 조작해야 하는 게임에서 집단화가 유닛별 명령을 숨겨서도 안 된다. 선택된 집단만 체력을 표시하는 것도 모든 게임에 맞는 규칙은 아니다. 이 조사는 상태 분리만 채택한다.

### Civilization VII 결정 문맥과 현재 상태

[Tom Shaw의 Firaxis 개발자 글](https://civilization.2k.com/civ-vii/game-guide/gameplay/developing-settlements/)은 [제작사 Steam 공지](https://steamcommunity.com/games/1295660/announcements/detail/520850995978177269)에서 2025년 9월 26일 게시로 확인했다. 글은 1.2.5 예정 변경이다. 제작자는 목록의 잠재 수치가 추천처럼 보이는 문제를 설명하고, 실제 배치 단계에 전후 변화와 손실을 연결한다.

원본 Placement After와 Detailed Yields 이미지를 실제로 열었다. 좁은 왼쪽 문맥 패널과 넓은 중앙 지도, PLACE BAZAAR 제목, BEFORE와 AFTER 구역, 부호가 있는 증감과 유지비, 지도 타일 표식이 보인다. 검은 반투명 면과 얇은 금색 선은 이 제품의 표현이다. 이를 모든 전략 게임의 미감으로 일반화하지 않는다.

교정 지시 STRAT4:R04: 함대 데모에서는 경제 화면을 새로 만들지 않는다. 현재 선택 집단과 현재 명령, 목적지 지정 문구를 같은 문맥 HUD에 붙이고, 지도상의 미리보기와 그 대상 이름을 연결한다. 추가 설명을 접어도 목표, 활성 명령, 취소, 실행 상태는 남긴다. 단순 데이터 강조를 ‘최선’, ‘추천’으로 부르지 않는다. 알려지지 않은 도착 시간이나 전투 예측은 만들어 표시하지 않는다.

예외: 턴제의 상세 손익 패널을 실시간 전투 중 매번 여는 설계는 그대로 옮길 수 없다. 원문도 일부 modifier와 인접 이유 표시의 한계를 기록한다. 이번 자료는 현재 2026년 제품의 완전성 검증이 아니다. 원작의 수치 변경과 새 정보 추가를 우리 합성 전후 시안의 근거로 혼합하지 않는다.

## 같은 fixture로 만드는 인터랙티브 전후 사양

이 사양은 자체 제안이다. 원작 스크린샷을 before로 쓰지 않는다. 자체 SVG 함대와 지도를 사용하고 source 이미지는 링크만 남긴다. 실제 demo/fixture.json은 960×680 월드에 아군 Kestrel, Arrow, Willow, 적군 Fang, Relay approach 목표를 정의한다. 기본 선택은 A1의 Kestrel이다. 이 파일과 상태 모듈의 해시는 JSON의 comparison_spec에 기록한다. 도형의 배경과 월드 좌표도 양쪽 공통이다.

조작은 아군 선택, Shift 추가 선택, Move 또는 Attack 선택, 목표 미리보기, Confirm order 확정, Stop order, Escape 취소다. M, A, S, Escape는 활성 프레임 안에서만 사용한다. Enter와 Space는 native 버튼 활성화만 담당한다. Before와 After 모두 같은 reducer와 행동을 사용한다. 화면 문구는 en-US이고 이 연구 설명은 한국어다. 데모는 명령을 기록하고 선을 그리며 이동이나 피해를 시뮬레이션하지 않는다. Arrow의 이동과 firing 문구는 fixture의 정적 상태다.

양쪽이 동일하게 유지할 항목은 집단 ID와 유닛 위치 및 수, 선택 집단, 체력과 명령 데이터, 목적지, 카메라, 지원 행동과 키, 취소 의미, viewport, DPR, 배율, locale, 실행 milestone이다. 같은 상태에서 보기만 전환하며 리셋 버튼은 양쪽 공통 상태를 초기화한다. 서로 다른 상태를 나란히 놓고 디자인 효과라고 주장하지 않는다.

Before는 같은 명령을 한 덩어리로 나열하고 hover, 선택, 지정 중 상태에 비슷한 강조를 사용한다. After는 집단과 선택 표식은 유지한 채 이동과 전투 동작을 구획하고, 현재 행동과 지정 중인 행동을 다른 문구 및 형상으로 표시한다. 입력 라우팅과 명령 결과는 양쪽 동일하다. HUD 재배치와 상태 표현만 시각 변경 장부에 허용한다.

자체 시안의 시각 출발점은 작은 모서리의 사각 native 버튼, 44px 높이, 본문 14px, 묶음 간격 8px, focus outline 2px다. 낮은 질감의 어두운 문맥 면에 label과 표식을 분명히 놓는다. 이는 제안한 CSS 값이며 원작에서 측정한 버튼 크기나 접근성 인증값이 아니다. 실제 데모의 CSS와 반응형 검수는 별도로 확인한다.

필수 캡처는 선택 없음, 집단 선택, 비선택 집단 hover, 키보드 focus, 이동 명령 지정 중, 유효 목표 미리보기, 유효하지 않은 공격 목표, 명령 기록 완료, 명령 취소다. 각 캡처에는 fixture 및 상태 해시, 렌더링 설정, 정확한 action sequence를 붙인다. 카메라 이동은 현재 데모에 없으므로 통합 검수용 제안으로만 남긴다. 이동과 교전의 동시 표시는 정적 fixture 상태의 표현만 확인할 수 있다. 제작자 설명을 기능이 없는 데모의 실행 결과로 대체하지 않는다.

## 구현자 검수 항목

1. 집단 클릭, HUD 명령 클릭, 월드 목적지 클릭의 결과를 각각 확인한다. 선택이 명령 실행으로 바뀌면 실패다.
2. Hover가 바뀌어도 선택 집단은 바뀌지 않는다. Focus와 selected가 정지 화면에서도 다르게 읽혀야 한다.
3. HUD 클릭의 pointer 이벤트가 월드 목표로 전파되지 않는다. 명령 지정 중 카메라를 움직여도 주문이 추가되지 않아야 한다는 기준은 카메라가 있는 실제 엔진 통합 때 별도로 검수한다. 현재 데모는 카메라 검수를 통과한 것으로 표시하지 않는다.
4. Escape가 지정 중 명령을 취소한 후 집단 선택을 유지한다. 양쪽 시안에서 같은 결과여야 한다.
5. 명령을 확정하면 ‘지정 중’은 종료되고 기록된 명령과 목표가 갱신된다. 입력 취소는 기존 명령 기록을 삭제하지 않는다. 실제 이동, 도착, 피해는 검수했다고 표시하지 않는다.
6. 작은 HUD에서도 필수 집단 수, 현재 상태, 활성 명령, 취소 조작을 읽을 수 있어야 한다. 전투 중 필요한 정보를 상세 화면에만 숨기면 실패다.
7. 좁은 viewport 및 큰 텍스트 설정에서도 명령이 잘리거나 월드 대상과 겹치지 않는지 확인한다. 버튼 크기 수치는 이 사례용 출발점이며 장르 표준이 아니다.
8. 효율 개선을 주장하려면 오명령, 재탐색, 완료시간을 별도 사용성 실험으로 측정한다. 이번 source inspection이나 수동 smoke test는 그런 측정이 아니다.

연구 런타임 상태는 not_tested다. 실제 데모와 QA의 상태는 별도 산출물에서 확인한다. 공개 GitHub 배포, Codex plugin 승인 또는 설치, Sites 수정은 이번 조사에 포함되지 않는다. 패키지는 링크와 자체 요약, 자체 fixture 및 도형만 포함하고 원본 스크린샷 바이트와 타사 폰트는 포함하지 않는다.
