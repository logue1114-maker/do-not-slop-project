# Original authored applications

These are full input packets, not isolated button redesigns or existing game source. All target visual/input/device/parity/review gates are not_run.

- `painted-entry.brief.json`: fictional short puzzle, entry -> ready -> play -> result -> actual Retry/Back contract; paper/ink face, shallow body, content-derived width and exact CSS-pixel trial values
- `industrial-adaptation.brief.json`: fictional dense route comparison, inspect -> selected -> pending -> authoritative result -> retained list context; low-relief rectangular rows, quiet opaque data surface, real readiness predicates and different exact geometry/type/motion trials

The second branch changes organizing plane, role/state and anatomy; it is not evidence that simply recoloring the paper shell fits a management interface. Both are explicitly authored assumptions and remain proposal-ready until the real source, strings, underlays, fonts, native units and input are supplied and rendered.

Command dimensions such as 60 or 44 CSS px are project trials, not universal touch minima, physical-device passes or dp/pt/Roblox values. Both pass record structure; neither has been implemented or visually accepted.

Run from the release root:

```sh
python validator.py brief examples/painted-entry.brief.json
python validator.py brief examples/industrial-adaptation.brief.json
```
