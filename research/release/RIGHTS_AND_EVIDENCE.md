# Sources, rights and evidence boundaries

## Public variant and private source boundary

This separately prepared public copy retains original authored instructions, conditional construction guidance, hypothetical application scenarios and original diagrams. Private repository and game identities, source paths/URLs, build metadata, selected-file counts and detailed inspection records are omitted. The private research copy remains separate and is not public evidence access.

The omission does not make a source claim independently reproducible. The published application scenarios are fictional authored guidance, not renamed source-game inspection records. Retained recipes remain conditional draft proposals. No new target rendering, input, runtime-unit calibration, persistence, multiplayer, complete game traversal or target acceptance is asserted.

Encoded image dimensions, logical viewports and device measurements are different quantities. A still cannot prove calibrated engine units, mobile layouts, physical touch, controller support or actual runtime behavior.

## Claim levels

- Source-visible: actually inspected pixels/content within the recorded scope
- Source-reported: manifests/telemetry claims attributed to their author
- Target-proposed: an original conditional plan or authored trial
- Target-rendered: requires actual identified target output; none produced here
- Behavior-tested: requires actual runtime/input evidence; none produced here
- User-approved: requires explicit review of a named rendered scope; none implied

The structure validator checks declared shapes, IDs and references only. It does not authenticate source truth, read pixels, run input, assess aesthetics, enforce legal rights or prove a recipe's causal effect. The finished framework and passing validation are deliverables; target production quality remains a separate gate.
